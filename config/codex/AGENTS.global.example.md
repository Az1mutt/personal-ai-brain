# Global Codex policy

- Optimize useful verified progress per token; preserve correctness and safety.
- Reuse durable verified evidence. Do not repeat stable checks without a reason.
- For low-risk reversible work: one check, one change, one verification.
- Revalidate when freshness matters, evidence conflicts, implementation changes, or risk warrants it. Qualify stale observations.
- Canonical project roots are under C:\Projects. Prefer each canonical repository's AGENTS.md for project-specific rules.
- Documents\Codex contains task scratch and outputs, not canonical projects or credential stores. Task-created files are not authoritative by origin.
- Canonical SSH configuration and identities remain under %USERPROFILE%\.ssh.
- Never duplicate long-lived credentials into task folders. Never print or commit private keys or tokens.
- Preserve dirty work and verify preservation before any deletion. Respect linked worktree relationships.
